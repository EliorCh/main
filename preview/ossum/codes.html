מעבדת קוד

כל התוכניות והפקודות של הקורס במקום אחד: מה המטרה של כל אחת, הקוד המלא, מה רואים כשמריצים אותה, ומה קורה שם בפועל.

כל פלט בעמוד הזה הוא פלט אמיתי. הרצתי את כל הדוגמאות כמשתמש vagrant על Ubuntu עם gcc, כמו ב-VM של הקורס. מה שישתנה אצלכם: מספרי ה-PID, התאריכים, ולפעמים הסדר של שורות מתהליכים שרצים במקביל. דוגמאות שמסומנות מהקורס מופיעות כמו שהן בחומרי הקורס.

הדרך המומלצת: לקרוא את המטרה, לנחש מה יודפס, ורק אז להסתכל על הטרמינל.

אין דוגמה שמתאימה לחיפוש.

טרמינל: פקודות שצריך להכיר

כל פקודה כאן היא תוכנית שה-shell מריץ בשבילכם. כדאי להריץ אותן ב-VM תוך כדי קריאה.

התמצאות: איפה אני ומה יש כאן

פרק 2 ↗

המטרה: לדעת בכל רגע באיזו תיקייה אתם עומדים ומה יש בה. כל פקודה רצה ביחס לתיקייה הנוכחית.

בטרמינל
$ pwd
/home/vagrant/nav
$ mkdir -p demo/sub
$ ls
demo
$ cd demo
$ pwd
/home/vagrant/nav/demo
$ ls -la
total 12
drwxrwxr-x 3 vagrant vagrant 4096 Nov 12 23:44 .
drwxr-xr-x 3 vagrant vagrant 4096 Nov 12 23:44 ..
drwxrwxr-x 2 vagrant vagrant 4096 Nov 12 23:44 sub
$ cd ..
$ pwd
/home/vagrant/nav
מה קורה כאן
  1. pwd מדפיס את הנתיב המלא של התיקייה הנוכחית (print working directory).
  2. mkdir -p demo/sub יוצר את demo ובתוכה sub בפקודה אחת. בלי -p, mkdir נכשל אם תיקיית האב לא קיימת.
  3. ls -la: -l פורמט ארוך (הרשאות, בעלים, גודל, תאריך) ו--a מציג גם קבצים שמתחילים בנקודה. כך רואים את . (התיקייה עצמה) ו-.. (תיקיית האב).
  4. התו הראשון בכל שורה הוא הסוג: d תיקייה, - קובץ רגיל.
  5. cd .. עולה רמה אחת. cd לבד חוזר לתיקיית הבית ~.
השורה התחתונה . = כאן, .. = למעלה, ~ = הבית. נתיב שלא מתחיל ב-/ הוא יחסי לתיקייה הנוכחית.

קבצים: יצירה, כתיבה, העתקה, מחיקה

פרק 2 ↗

המטרה: הפעולות הבסיסיות על קבצים, ומה ההבדל בין > ל->>.

בטרמינל
$ echo "first line" > notes.txt
$ echo "second line" >> notes.txt
$ cat notes.txt
first line
second line
$ echo "oops" > notes.txt
$ cat notes.txt
oops
$ cp notes.txt copy.txt
$ mv copy.txt renamed.txt
$ touch empty.txt
$ ls -l
total 8
-rw-rw-r-- 1 vagrant vagrant 0 Nov 12 23:44 empty.txt
-rw-rw-r-- 1 vagrant vagrant 5 Nov 12 23:44 notes.txt
-rw-rw-r-- 1 vagrant vagrant 5 Nov 12 23:44 renamed.txt
$ rm renamed.txt empty.txt
$ ls
notes.txt
מה קורה כאן
  1. > מפנה את הפלט לקובץ ודורס אותו. >> מוסיף לסופו.
  2. ה-echo "oops" > notes.txt מחק את שתי השורות הקודמות. אין "בטוח?" ואין סל מחזור.
  3. mv משמש גם להעברה וגם לשינוי שם: באותה תיקייה זה פשוט שינוי שם.
  4. touch יוצר קובץ ריק (גודל 0 ב-ls -l).
  5. rm מוחק מיד. לתיקייה: rm -r, ובזהירות.
השורה התחתונה > דורס, >> מוסיף. גם rm וגם > לא שואלים לפני שהם מוחקים.

הרשאות: למה ./script.sh לא רץ

פרק 2 ↗

המטרה: להבין את מחרוזת ההרשאות ב-ls -l, ולמה צריך chmod +x לפני שמריצים סקריפט.

hello.sh
#!/bin/bash
echo "hello from $0"
בטרמינל
$ ls -l hello.sh
-rw-r--r-- 1 vagrant vagrant 33 Nov 12 23:44 hello.sh
$ ./hello.sh
bash: line 6: ./hello.sh: Permission denied
$ chmod u+x hello.sh
$ ls -l hello.sh
-rwxr--r-- 1 vagrant vagrant 33 Nov 12 23:44 hello.sh
$ ./hello.sh
hello from ./hello.sh
$ chmod 750 hello.sh
$ ls -l hello.sh
-rwxr-x--- 1 vagrant vagrant 33 Nov 12 23:44 hello.sh
$ chmod 700 hello.sh
$ ls -l hello.sh
-rwx------ 1 vagrant vagrant 33 Nov 12 23:44 hello.sh
מה קורה כאן
  1. קובץ חדש נוצר בלי הרשאת הרצה (x), ולכן ההרצה נכשלת ב-Permission denied.
  2. rw-rw-r-- מתחלק לשלוש שלשות: בעלים (u), קבוצה (g), אחרים (o). בכל שלשה: קריאה, כתיבה, הרצה.
  3. chmod u+x מוסיף הרצה רק לבעלים, ומשאיר את השאר כמו שהם.
  4. בצורה המספרית כל שלשה היא סכום: r=4, w=2, x=1. לכן 750 = rwxr-x--- ו-700 = rwx------.
  5. הצורה המספרית קובעת את כל ההרשאות מחדש; הצורה עם +/- משנה רק את מה שכתוב.
השורה התחתונה Permission denied בהרצה של קובץ שלכם = חסר x. התיקון: chmod u+x.

קומפילציה: -Wall, אזהרות וקוד יציאה

פרק 2 ↗

המטרה: לקמפל בדיוק כמו הבודק, לקרוא אזהרה, ולראות את הערך שהתוכנית מחזירה.

warn.c
#include <stdio.h>

int main() {
    int unused;
    int x;
    printf("x = %d\n", x);
    return 3;
}
בטרמינל
$ gcc warn.c -o warn
$ gcc warn.c -Wall -o warn
warn.c: In function ‘main’:
warn.c:4:9: warning: unused variable ‘unused’ [-Wunused-variable]
    4 |     int unused;
      |         ^~~~~~
warn.c:6:5: warning: ‘x’ is used uninitialized [-Wuninitialized]
    6 |     printf("x = %d\n", x);
      |     ^~~~~~~~~~~~~~~~~~~~~
warn.c:5:9: note: ‘x’ was declared here
    5 |     int x;
      |         ^
$ ./warn
x = 32766
$ echo $?
0
מה קורה כאן
  1. בלי -Wall הקומפילציה עברה בשקט, למרות שיש בקוד שתי בעיות.
  2. עם -Wall: unused variable – משתנה שהוגדר ולא בשימוש, ו-is used uninitialized – משתנה שקוראים לפני שנתנו לו ערך. השני הוא באג אמיתי: הערך המודפס הוא מה שהיה במקרה בזיכרון.
  3. אזהרה לא עוצרת את הקומפילציה: קובץ הריצה נוצר ורץ. אבל בתרגילי הקורס כל אזהרה מורידה נקודות.
  4. הערך ש-main מחזיר הוא קוד היציאה, ו-$? מציג אותו מיד אחרי ההרצה: 3.
השורה התחתונה מקמפלים תמיד עם -Wall, ומתקנים כל אזהרה. היא כמעט תמיד מצביעה על באג.

ארגומנטים: מה התוכנית באמת מקבלת

פרק 3 ↗

המטרה: לראות איך ה-shell מפרק שורת פקודה ל-argv – כולל מרכאות ו-$.

args.c
#include <stdio.h>

int main(int argc, char *argv[]) {
    printf("argc = %d\n", argc);
    for (int i = 0; i < argc; i++)
        printf("argv[%d] = [%s]\n", i, argv[i]);
    return 0;
}
בטרמינל
$ gcc args.c -Wall -o args
$ ./args one   two
argc = 3
argv[0] = [./args]
argv[1] = [one]
argv[2] = [two]
$ ./args "one   two"
argc = 2
argv[0] = [./args]
argv[1] = [one   two]
$ ./args $HOME '$HOME'
argc = 3
argv[0] = [./args]
argv[1] = [/home/vagrant]
argv[2] = [$HOME]
$ ./args *.c
argc = 2
argv[0] = [./args]
argv[1] = [args.c]
מה קורה כאן
  1. argv[0] הוא שם התוכנית כפי שהורצה, ולכן argc תמיד גדול ב-1 ממספר הארגומנטים.
  2. רווחים מרובים בין מילים לא נכנסים לתוכנית: ה-shell מפצל לפי רווחים לפני שהוא מריץ.
  3. בתוך מרכאות כפולות הרווחים נשמרים, והכל ארגומנט אחד.
  4. $HOME מוחלף בערך לפני שהתוכנית רצה; בתוך מרכאות בודדות לא. גם *.c מוחלף ברשימת הקבצים לפני ההרצה – התוכנית מקבלת args.c, לא כוכבית.
השורה התחתונה התוכנית לא רואה את שורת הפקודה. היא רואה רק את argv שה-shell כבר פירק, החליף והוריד ממנו מרכאות.

הפניות: ‎&lt;‎, ‎&gt;‎ ו-‎2&gt;‎

פרק 6 ↗

המטרה: לשלוח פלט לקובץ, לקרוא קלט מקובץ, ולהפריד הודעות שגיאה מפלט רגיל.

names.txt
dana
omer
yael
בטרמינל
$ wc -l < names.txt
3
$ sort -r names.txt > sorted.txt
$ cat sorted.txt
yael
omer
dana
$ ls names.txt nosuchfile
ls: cannot access 'nosuchfile': No such file or directory
names.txt
$ ls names.txt nosuchfile > out.txt 2> err.txt
$ cat out.txt
names.txt
$ cat err.txt
ls: cannot access 'nosuchfile': No such file or directory
מה קורה כאן
  1. < names.txt מחבר את הקובץ ל-stdin של wc. לכן wc מדפיס רק מספר, בלי שם קובץ – הוא לא יודע מאיפה הגיע הקלט.
  2. > sorted.txt מחבר את stdout לקובץ. על המסך לא מודפס כלום.
  3. ls עם קובץ שקיים ואחד שלא: שתי שורות על המסך, אבל הן הגיעו משני ערוצים שונים – stdout (1) ו-stderr (2).
  4. 2> err.txt מפנה רק את ערוץ 2. ההפרדה מראה בדיוק מה הלך לאן.
השורה התחתונה < = stdin, > = stdout, 2> = stderr. perror כותבת לערוץ 2, ולכן הודעות שגיאה לא נכנסות לקובץ פלט רגיל.

צינורות: לחבר פקודות

פרק 6 ↗

המטרה: לבנות מפקודות קטנות כלי שעונה על שאלה, כשהפלט של אחת הוא הקלט של הבאה.

log.txt
GET /home 200
GET /about 404
POST /login 200
GET /home 200
GET /missing 404
GET /home 500
בטרמינל
$ cat log.txt | wc -l
6
$ grep 404 log.txt
GET /about 404
GET /missing 404
$ grep -c 200 log.txt
3
$ cut -d" " -f3 log.txt | sort | uniq -c
      3 200
      2 404
      1 500
$ head -3 log.txt | tail -1
POST /login 200
מה קורה כאן
  1. | מחבר את stdout של הפקודה משמאל ל-stdin של הפקודה מימין. שתיהן רצות במקביל, כשני תהליכים.
  2. grep מסנן שורות שמכילות מחרוזת; -c סופר אותן במקום להדפיס.
  3. cut -d" " -f3 לוקח את השדה השלישי (מופרד ברווח), sort ממיין, ו-uniq -c סופר שורות זהות צמודות – לכן חייבים sort לפניו.
  4. head -3 | tail -1 = השורה השלישית בדיוק.
השורה התחתונה כל פקודה עושה דבר אחד, והצינור מחבר ביניהן. ב-C זה pipe + dup2 + fork (פרק 6).

תהליכים: ‎&amp;‎, ‎ps‎ ו-‎kill‎

פרק 5 ↗

המטרה: להריץ תהליך ברקע, לראות אותו ברשימת התהליכים, ולעצור אותו עם סיגנל.

בטרמינל
$ sleep 300 &
[1] 1039
$ ps -o pid,ppid,stat,cmd
  PID  PPID STAT CMD
 1038  1037 Ss+  bash -s
 1039  1038 S+   sleep 300
 1040  1038 R+   ps -o pid,ppid,stat,cmd
$ kill 1039
$ ps -o pid,ppid,stat,cmd
  PID  PPID STAT CMD
 1038  1037 Ss+  bash -s
 1042  1038 R+   ps -o pid,ppid,stat,cmd
מה קורה כאן
  1. & מריץ את sleep ברקע: ה-shell מדפיס את מספר העבודה ואת ה-PID, ומחזיר את ה-prompt מיד.
  2. ב-ps: ה-PPID של sleep הוא ה-PID של bash – ה-shell הוא ההורה שעשה לו fork.
  3. עמודת STAT: S = ישן (חסום, מחכה), R = רץ. ps עצמו רץ ברגע הצילום.
  4. kill PID שולח SIGTERM כברירת מחדל. sleep לא תופס אותו, ולכן מסתיים, ונעלם מהרשימה.
השורה התחתונה כל פקודה שמריצים היא תהליך שה-shell יצר. kill הוא שליחת סיגנל, לא בהכרח הריגה.

משתני סביבה: מה עובר לתהליך ילד

פרק 2 ↗

המטרה: להבין למה משתנה שהגדרתם לא נראה בתוכנית שהרצתם, ומה export עושה.

בטרמינל
$ echo "$USER lives in $HOME"
vagrant lives in /home/vagrant
$ COLOR=blue
$ echo $COLOR
blue
$ bash -c 'echo "child sees: [$COLOR]"'
child sees: []
$ export COLOR
$ bash -c 'echo "child sees: [$COLOR]"'
child sees: [blue]
$ COLOR=red bash -c 'echo "one-time: [$COLOR]"'
one-time: [red]
מה קורה כאן
  1. $USER ו-$HOME מוגדרים כבר בכניסה, וכל תוכנית מקבלת אותם.
  2. COLOR=blue (בלי רווחים סביב ה-=) יוצר משתנה של ה-shell בלבד.
  3. bash -c מריץ shell חדש – תהליך ילד. הוא לא רואה את COLOR, כי משתנה רגיל לא עובר ב-fork/exec.
  4. אחרי export המשתנה הוא חלק מהסביבה, וכל ילד מקבל עותק.
  5. VAR=value command מגדיר את המשתנה רק להרצה הזו.
השורה התחתונה ילד מקבל עותק של הסביבה בזמן היצירה. שינוי אצל הילד לא חוזר להורה – כמו כל זיכרון אחרי fork.

קוד יציאה, ‎&amp;&amp;‎ ו-‎;‎

פרק 2 ↗

המטרה: לשרשר פקודות כך שהבאה תרוץ רק אם הקודמת הצליחה.

בטרמינל
$ ls /nope; echo "code: $?"
ls: cannot access '/nope': No such file or directory
code: 2
$ ls /nope && echo "will not print"
ls: cannot access '/nope': No such file or directory
$ ls /nope; echo "prints anyway"
ls: cannot access '/nope': No such file or directory
prints anyway
$ ls / > /dev/null && echo "ls succeeded"
ls succeeded
$ ls /nope || echo "runs because ls failed"
ls: cannot access '/nope': No such file or directory
runs because ls failed
מה קורה כאן
  1. כל פקודה מחזירה מספר: 0 = הצלחה, כל דבר אחר = כישלון. $? הוא הקוד של הפקודה האחרונה.
  2. A && B: B רץ רק אם A החזיר 0.
  3. A ; B: B רץ בכל מקרה.
  4. A || B: B רץ רק אם A נכשל.
  5. /dev/null הוא "פח": מה שנכתב אליו נעלם. שימושי כשרק קוד היציאה מעניין.
השורה התחתונה אותו היגיון של קיצור-דרך כמו && ו-|| ב-C, רק ש-0 פירושו "הצלחה".

strace: לראות את קריאות המערכת

פרק 3 ↗

המטרה: לראות בעיניים מה תוכנית מבקשת מהקרנל: מה printf הופך להיות, ומה קורה ב-fork וב-exec.

st.c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    printf("hello\n");
    if (fork() == 0) {
        char *args[] = { "echo", "from child", NULL };
        execvp(args[0], args);
    }
    wait(NULL);
    return 0;
}

  3. printf("hello\n") הפך ל-write(1, "hello\n", 6): כתיבה ל-FD 1. זו ההוכחה ש-printf היא פונקציית ספרייה מעל קריאת מערכת.
  4. fork מופיע כ-clone: ב-Linux fork ממומש מעליו. הערך שחזר הוא ה-PID של הילד.
  5. execvp הפך ל-execve עם נתיב מלא: execvp חיפש את echo בתיקיות של PATH. ניסיון שנכשל מופיע עם ENOENT.
  6. wait הוא wait4 שמחכה, ולבסוף exit_group – הסיום.
השורה התחתונה strace הוא הדרך לבדוק מה תוכנית באמת עושה ברמת מערכת ההפעלה. שימושי במיוחד כשמשהו "לא קורה" ולא ברור למה.

            sleep(i);
            _exit(i);
        }

    pid_t pid;

    printf("no more children\n");
    return 0;
}

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>

void report(int status) {
    if (WIFEXITED(status))
        printf("exited normally, code %d\n", WEXITSTATUS(status));
    else if (WIFSIGNALED(status))
        printf("killed by signal %d\n", WTERMSIG(status));
}

int main() {
    int status;
    if (fork() == 0) exit(42);              // child 1: exits with 42
    wait(&status);
    report(status);

    pid_t pid = fork();
    if (pid == 0) { while (1) sleep(1); }   // child 2: never ends by itself
    kill(pid, SIGKILL);
    waitpid(pid, &status, 0);
    report(status);
    return 0;
}

exec.c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    int rc = fork();
    if (rc < 0) { fprintf(stderr, "fork failed\n"); exit(1); }
    else if (rc == 0) {                      // child
        char *args[] = { "wc", "-l", "exec.c", NULL };
        execvp(args[0], args);
        printf("this shouldn't print out\n"); // only if exec failed
    } else {                                 // parent
        int rc_wait = wait(NULL);
        printf("I am parent of %d (rc_wait:%d) (pid:%d)\n", rc, rc_wait, getpid());
    }
    return 0;
}

תוכנית ש-Ctrl+C לא עוצר

מהקורספרק 5 ↗

המטרה: להחליף את טיפול ברירת המחדל בסיגנל ב-handler משלנו.

sigint.c
#include <sys/time.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>

void sigint_handler(int sig) {
    printf("SIGINT ignored: %d\n", getpid());
}

int main(int argc, char *argv[])
{
    struct sigaction act;
    sigemptyset(&act.sa_mask);
    act.sa_handler = sigint_handler;
    act.sa_flags = 0;

    if (sigaction (SIGINT, &act, NULL) == -1) {
        fprintf(stderr, "sigaction failed\n");
        exit(1);
    }

    printf("%d ignoring SIGINT\n", getpid());
    while (1);
    return 0;
}

SIGCHLD קוטע את sleep

מהקורספרק 5 ↗

המטרה: לראות שסיגנל מעיר תהליך שחסום בקריאת מערכת, ולמה הקוד ישן בלולאה.

sigchld.c
#include <sys/time.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>

void sigchld_handler(int signal) {
    int rc = wait(NULL);
    printf("%d: Child %d terminated\n", getpid(), rc);
}
int main(int argc, char *argv[])
{
    struct sigaction act;
    sigemptyset(&act.sa_mask);
    act.sa_handler = sigchld_handler; //or: act.sa_handler = SIG_IGN;
    act.sa_flags = 0;

    if (sigaction(SIGCHLD, &act, NULL) == -1) {
        fprintf(stderr, "sigaction failed\n");
        exit(1);
    }

    while (1) {
        if (!fork()) {
            sleep(1);
            break;
        }
        int slp = 5;
        while (slp) {
            slp = sleep(5);
        }
    }
    return 0;
}

wait שאוסף את הילד הלא נכון

#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

    if (fg == 0) { sleep(2); _exit(0); }   // "foreground" child: 2 seconds

    return 0;
}

איסוף בלי לחסום: WNOHANG

פרק 5 ↗

המטרה: הורה שממשיך לעבוד, ובכל סיבוב אוסף את מי שסיים – בלי לחכות ובלי סיגנלים.

workers.c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    setbuf(stdout, NULL);
    for (int i = 1; i <= 3; i++) {
        pid_t pid = fork();
        if (pid < 0) { perror("fork"); return 1; }
        if (pid == 0) { sleep(i); _exit(0); }   // worker i runs i seconds
        printf("started worker %d\n", pid);
    }
    int left = 3;
    while (left > 0) {
        printf("parent busy...\n");
        sleep(1);
        pid_t done;
        while ((done = waitpid(-1, NULL, WNOHANG)) > 0) {   // collect everyone who finished
            printf("worker %d finished\n", done);
            left--;
        }
    }
    return 0;
}

EINTR: קריאה חוסמת שנקטעה

פרק 5 ↗

המטרה: לראות ש-handler ל-SIGCHLD גורם ל-read ול-waitpid להיכשל באמצע.

eintr.c
#include <stdio.h>
#include <string.h>
#include <signal.h>
#include <unistd.h>
#include <sys/wait.h>

void on_child(int sig) { while (waitpid(-1, NULL, WNOHANG) > 0) ; }

int main() {
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = on_child;              /* no SA_RESTART */
    sigaction(SIGCHLD, &sa, NULL);

    pid_t bg = fork();
    if (bg == 0) { sleep(1); _exit(0); }   /* ends after 1 second */
    pid_t fg = fork();
    if (fg == 0) { sleep(2); _exit(0); }   /* ends after 2 seconds */

    pid_t r = waitpid(fg, NULL, 0);        /* blocked here when bg ends */
    if (r < 0) perror("waitpid");
    else printf("waitpid returned %d\n", r);
    return 0;
}

מה קורה כאן

  2. אחרי שנייה הילד השני מסתיים. SIGCHLD מגיע, ה-handler רץ ואוסף אותו.

הפתרון מהקורס לתרגיל הסיגנלים

מהקורספרק 5 ↗

המטרה: handler אחד לשני סיגנלים, והחלפה בין טיפול בזומבים לברירת מחדל בכל Ctrl+C.

ex5.c
#include <sys/time.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <time.h>

pid_t last_child = 0;
struct sigaction act1;
struct sigaction act2;

void create_child() {
    last_child = fork();
    if (!last_child) {
        // child process
        printf("%d [%d] Child running\n", getpid(), getppid());
        sleep(5);
        exit(0);
    }
}

void signal_handler(int signal) {
    if (signal == SIGINT) {
        if (last_child) {
            printf("%d stopping child %d\n", getpid(), last_child);
            kill(last_child, SIGKILL);
            last_child = 0;
        }
        else {
            create_child();
        }
        struct sigaction tmp = act1;
        act1 = act2;
        act2 = act1;
        if (act1.sa_handler == signal_handler)
            printf("%d handling SIGCHLD\n", getpid());
        else
            printf("%d default SIGCHLD\n", getpid());

        if (sigaction(SIGCHLD, &act1, &act2) == -1) {
            fprintf(stderr, "sigaction SIGCHLD failed\n");
            exit(1);
        }
    }
    else if (signal == SIGCHLD) {
        int rc = wait(NULL);
        printf("%d: Child %d terminated\n", getpid(), rc);
        last_child = 0;
        create_child();
    }
}

int main(int argc, char *argv[])
{
    sigemptyset(&act1.sa_mask);
    act1.sa_handler = signal_handler; //or: act.sa_handler = SIG_IGN;
    act1.sa_flags = 0;

    if (sigaction(SIGCHLD, &act1, &act2) == -1) {
        fprintf(stderr, "sigaction SIGCHLD failed\n");
        exit(1);
    }
    if (sigaction(SIGINT, &act1, NULL) == -1) {
        fprintf(stderr, "sigaction SIGINIT failed\n");
        exit(1);
    }

    while (1) {
        sleep(1);
    }
    return 0;
}

dup: המספר הפנוי הנמוך ביותר

פרק 6 ↗

המטרה: להבין איך printf יכולה לכתוב לקובץ: FD 1 מצביע לקובץ במקום למסך.

dup.c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int f = open("x.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    int a = dup(f);
    fprintf(stderr, "f=%d a=%d\n", f, a);
    close(1);
    int b = dup(f);
    fprintf(stderr, "b=%d\n", b);
    printf("to file\n");
    return 0;
}

מה קורה כאן

  2. dup(f) יוצר עוד מספר שמצביע לאותו קובץ, ותמיד לוקח את המספר הפנוי הנמוך ביותר: 4.
  3. אחרי close(1) המספר הפנוי הנמוך ביותר הוא 1, ולכן dup מחזירה 1. עכשיו FD 1 מצביע ל-x.txt.

השורה התחתונה ככה ה-shell מממש >: סוגר את 1 ומשכפל לתוכו את הקובץ. dup2(fd, 1) עושה את שני השלבים בפעולה אחת.

הפניית הפלט של ילד לקובץ

פרק 6 ↗

המטרה: לממש ls > out.txt בעצמנו: fork, dup2 ואז exec.

redirect.c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t rc = fork();
    if (rc == 0) {
        int fd = open("out.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
        if (fd == -1) { perror("open"); exit(1); }
        dup2(fd, STDOUT_FILENO);   // FD 1 now points to out.txt
        close(fd);                 // the copy in FD 1 is enough
        char *args[] = { "ls", NULL };
        execvp(args[0], args);     // ls writes to FD 1 without knowing
        perror("execvp"); exit(1);
    }
    waitpid(rc, NULL, 0);
    printf("parent: ls is done, its output is in out.txt\n");
    return 0;
}

צינור בין שני תהליכים: ls | wc -l

פרק 6 ↗

המטרה: לממש צינור: הפלט של ילד אחד הוא הקלט של ילד שני.

pipe.c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    int fd[2];
    pipe(fd);                          // fd[0] = read end, fd[1] = write end
    if (fork() == 0) {                 // first child: ls
        dup2(fd[1], STDOUT_FILENO);
        close(fd[0]); close(fd[1]);
        execlp("ls", "ls", NULL);
        perror("ls"); exit(1);
    }
    if (fork() == 0) {                 // second child: wc -l
        dup2(fd[0], STDIN_FILENO);
        close(fd[0]); close(fd[1]);
        execlp("wc", "wc", "-l", NULL);
        perror("wc"); exit(1);
    }
    close(fd[0]); close(fd[1]);        // parent must close too
    while (wait(NULL) > 0);
    return 0;
}

מה קורה כאן

  3. כל תהליך סוגר את כל הקצוות שהוא לא משתמש בהם – כולל ההורה. wc מסיים רק כשהוא רואה סוף קלט, וזה קורה רק כשכל מי שמחזיק את קצה הכתיבה סגר אותו.
  4. התוצאה זהה ל-ls | wc -l מהטרמינל.
השורה התחתונה קצה כתיבה ששכחו לסגור = wc מחכה לנצח. זו הטעות הכי נפוצה בצינורות.
